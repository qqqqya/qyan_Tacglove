# PB6按键与数据采集状态机说明

## 1. 当前实现目的

PB6已经由CubeMX配置为输入上拉。按键断开时读取高电平，按下后PB6接地，
读取低电平。当前使用“周期扫描 + 软件消抖 + FreeRTOS队列”实现按键控制，
没有启用EXTI中断。

对机械按键而言，20 ms周期扫描足以满足人机响应速度，也能把抖动处理放在
普通任务上下文中，避免在中断服务函数中操作业务状态或调用不合适的RTOS接口。

## 2. 软件分层

```text
PB6 GPIO
   ↓
BSP/KEY/bsp_key_handler       只解释“低电平等于按下”
   ↓
User_tasks/key_task           20 ms扫描、约60 ms消抖、一次按下只触发一次
   ↓
User_tasks/system_event       FreeRTOS Queue传递SYSTEM_EVENT_CAPTURE_KEY_PRESSED
   ↓
User_tasks/led_task           消费事件并运行采集状态机
   ├── BSP/LED                显示设备灯和LED7状态
   ├── BSP/BEEP               开始/结束时短鸣一次
   └── TODO采集任务队列       后续接入相机、存储和通信任务
```

按键BSP层没有再添加Driver，因为该模块只有一个GPIO读取操作。Handler已经隔离
PB6引脚和低电平有效这两个板级细节，再增加Driver只会形成无意义的一层转发。

## 3. 实际实验现象

1. 上电后LED1～LED6绿色闪烁3次，约持续1.5秒，表示正在进行上电自检。
2. 自检占位流程通过后，LED1～LED6绿色常亮，LED7熄灭，进入待机。
3. 短按PB6一次：LED7蓝色闪烁3次，表示采集准备中。
4. 准备结束后蜂鸣器短响约120 ms；蜂鸣结束后LED7蓝色常亮，表示采集中。
5. 再短按PB6一次：停止采集占位流程，蜂鸣器短响约120 ms，然后LED7熄灭，
   LED1～LED6保持绿色常亮，返回待机。
6. LED、蜂鸣器、事件队列或未来采集设备出现不可恢复错误时，七颗灯尝试
   红色常亮，表示硬件故障、通信中断或数据丢包等故障。

长按按键只产生一次事件。必须先松开并再次按下，才会产生下一次事件。
上电自检过程中产生的按键事件会被清除，必须进入待机后重新按键。

## 4. 当前占位内容

因为相机和数据采集链路还没有接入，以下操作只保留了明确的TODO，不会访问
不存在的硬件：

- 五路USB相机枚举、通信和帧数据检查；
- 鱼眼相机枚举、通信和帧数据检查；
- 存储介质容量、写入和数据落盘检查；
- 向采集任务发送开始/停止命令并等待确认；
- 通信中断、缓存溢出和数据丢包统计。

后续相机接入时，应让独立采集任务拥有相机驱动资源。LED状态任务只通过任务
队列发送“开始/停止”命令并等待结果，不能直接操作USB或相机寄存器。

## 5. 关键参数

| 参数 | 当前值 | 所在文件 |
| --- | ---: | --- |
| 按键扫描周期 | 20 ms | `User_tasks/key_task.c` |
| 消抖确认样本 | 3次，约60 ms | `User_tasks/key_task.c` |
| 系统事件队列长度 | 4条 | `User_tasks/system_event.c` |
| 自检绿色闪烁 | 3次，250 ms半周期 | `User_tasks/led_task.c` |
| 准备蓝色闪烁 | 3次，250 ms半周期 | `User_tasks/led_task.c` |
| 蜂鸣器确认声 | 120 ms | `User_tasks/led_task.c` |

## 6. 重新生成CubeMX代码时

PB6应继续保持：

- GPIO Input；
- Pull-up；
- 标签 `KEY_Capdata`；
- 按键另一端接GND。

当前方案不需要配置GPIO EXTI，也不需要增加PB6中断处理函数。如果将来按键需要
从低功耗睡眠唤醒MCU，再把PB6改为下降沿EXTI，并且只在ISR中使用
`xQueueSendFromISR()`投递事件，业务状态机仍然保留在任务层。
